// agent-operating-system

运行在 agent harness 上的个人文件治理层

AI 编程工具能写代码、跑命令，但不管你的文件：交付物散在工作目录里、知识存了三份彼此矛盾、会话一压缩约束就丢。AOS 解决的是这一层的问题，它给工具一套关于「东西放哪、知识存哪、状态记哪」的约定，并且这些约定可以被脚本检查。

形象点讲，AOS 的定位类似《钢铁侠》里的贾维斯：战衣换了几代，贾维斯一直都在。即便未来 AI 工具不时更换，秩序和记忆也可以持续跟着走。

§01
§ 01 · PAIN

工具很强，文件没人管

如果你经常让 AI 助手干活，这些场景应该不陌生。

01

交付物散落

代码写完了，产物散在工作目录各处。交付靠手动翻找，版本靠文件名后缀猜。

02

知识重复矛盾

同一份知识存了三处，改了一处忘了两处。下次 AI 读到的是过期版本。

03

会话压缩丢约束

上下文一压缩，「这个文件不要放这里」就得重讲一遍。纠正过的事反复再犯。

04

换工具从零开始

平台一换，规则、记忆、流程全留在旧工具里。新助手要从头教起。

无约定的工作目录 → AOS 目录宪章
§02
§ 02 · WORKFLOW

一个任务在 AOS 里的完整流转

从立项到归档，每一步都有约定的位置和可查的痕迹。

01

立项

模板起步

新项目按标准两件套（AGENTS.md + README.md）开局，目录骨架由 project-init skill 生成，也可以直接复制示例项目改名起步。

01_PROJECTS/{name}/AGENTS.mdREADME.mdskill: project-init

无 AOS：手动建目录写样板，每个项目从空白开始

02

工作过程

落位与记忆

创建任何文件前先查落位约定；状态类记忆覆盖旧值留注释，记录类只追加；关键会话一行写入叙事层索引。

04_MEMORY/INDEX.md06_LOGS/skill: file-placement

无 AOS：上下文只存于对话窗口，关闭即失忆

03

交付

唯一出口

交付物一律经 07_EXPORTS 按项目分层导出，禁止散落在工作目录；项目状态同步写回记忆中心，下次接手不用翻聊天记录。

07_EXPORTS/{project}/04_MEMORY/project/

无 AOS：交付物散落各处，进度追溯靠考古

04

巡检

机器管机器

校验脚本扫出散落文件、非标命名、结构漂移；巡检 skill 定期产出缓存清理清单。约定由脚本盯着执行。

scripts/check_placement.pyskill: inspection

无 AOS：改了一处忘了十处，问题潜伏到报障才暴露

05

归档与迁移

换平台随迁

废弃不删，进只读归档；叙事层日志与知识库是人类可读的纯文本，换平台时整体搬走，新工具读完约定即可接手。

99_ARCHIVE/06_LOGS/09_REFERENCE/

无 AOS：一切留在旧工具里，换平台从零开始

§ 04 · MECHANISMS

五个机制，各司其职

它们怎么协同运转，见仓库里的架构参考文档。

01 / 05

目录宪章

8 个编号目录，每个一行职责和几条约束，写在 AGENTS.md 里。AI 在创建任何文件之前先查约定，你不再需要反复纠正「这个文件不要放这里」。

# AGENTS.md
01_PROJECTS/ → 项目隔离
04_MEMORY/   → 状态中心
07_EXPORTS/ → 唯一出口 ▮
02 / 05

指针表记忆

INDEX.md 一行一指针加一段短描述，单文件 32KB 上限。状态类记忆覆盖旧值并留变更注释；记录类记忆只追加，历史剪入日志不丢。

# 04_MEMORY/INDEX.md
- user_profile → user/user_profile.md
- proj_aos → project/proj_aos.md （2026-06-15 更新，原为 v1.1.0） ▮
03 / 05

双层日志

过程细节交给平台自带的会话档案；治理层面的大事写入人类可直接阅读的 06_LOGS。换平台时，叙事层日志可以整体搬走。

叙事层 · 06_LOGS — 人类可读，平台无关，只追加
↑ 治理事件提炼
细节层 · 平台会话档案 — 最全过程，随平台更换
04 / 05

治理 skills

落位判定、知识入库、子代理调度、巡检流程等，各自是一个按需加载的技能文件，带实战沉淀的 gotchas 段落。犯错沉淀进 skill，比在提示词里纠正更持久。

file-placementinspectionsubagent-dispatchknowledge-ingestproject-init+2
05 / 05

环境对齐

一份 manifest 登记所有依赖组件，换机器或迁移环境时跑一个脚本即可检测缺什么。

$ python scripts/align_environment.py
[OK] skills 7/7 · scripts 4/4
[--] 缺失项按 manifest 列出 ▮
§05
§ 05 · DIRECTORIES

目录宪章：点开看约束

每个目录一个职责，关键约束写在 AGENTS.md 里，校验脚本盯着执行。

关键约束：项目模板两件套 AGENTS.md + README.md；根层禁止代码脚本散放；项目内只引用记忆与知识库路径，不复制内容

关键约束：状态型文件单文件 ≤32KB，超限剪切历史至日志目录并留指针；INDEX.md 一行一指针，≤200 行

关键约束：唯一副本禁入；按项目/日期两级分层；超期由巡检出清理清单；禁止任何长期引用指向此目录

关键约束：只追加；治理事件与项目关键节点必写一行；跨平台迁移时本目录随迁

关键约束：按项目分层；无项目的轻量任务进 quicktasks 日期分层目录

关键约束：按日期分层；处理完必须迁往真正归宿，原处只留去向指针

关键约束：知识只存一份，他处只写路径引用

关键约束：只读；只增不减

§ 06 · PLATFORMS

平台支持

FULL

DeepSeek Harness

skills 自动发现与按需加载、上下文压缩锚点、会话索引脚本等全部能力。v2 的实测在 DSH 上完成。

GENERAL

任何读取 AGENTS.md 的工具

通用适配也不是二手体验：把仓库交给你的 AI 工具，它读一遍约定，就能把这些规则适配成自己平台的形式，不需要手动改。

§07
§ 07 · GETTING STARTED

如何上手

最直接的方式：把这句话发给你正在用的 AI 工具（DSH、Claude Code、Codex 等均可），让它替你完成。

PROMPT · 交给你的 AI 执行

部署 AOS：克隆 https://github.com/MagicalYuYu/agent-operating-system 到 <你的目标路径>，阅读仓库根目录的 AGENTS.md 理解目录约定，运行 python scripts/check_placement.py 验证结构、有报错按提示修复，最后告诉我使用时需要注意的约定要点。

手动完成（6 步）
  1. 环境：Python 3.10+；读取 AGENTS.md 约定的工具即为通用适配，完整适配需 DSH。
  2. 放置：把仓库克隆到任意路径，无硬编码要求。
  3. 校验：运行 python scripts/check_placement.py，退出码 1 表示有 error 级违规，按提示修复。
  4. 对齐（可选）：按实际依赖编辑 .dsh/skill-manifest.json，再跑 python scripts/align_environment.py 检测缺失组件。
  5. 第一个项目：参照 01_PROJECTS/_example_* 示例项目的两件套起步，示例自带可运行的测试命令。
  6. 读内核：AGENTS.md（约 90 行），含目录宪章、4 条铁律、落位速查、行为不变量。
