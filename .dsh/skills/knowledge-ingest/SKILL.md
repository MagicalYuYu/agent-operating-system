# 知识入库（WKIS v2）

## 压缩前记忆冲刷

token >70% 时主动将关键上下文写入文件：任务+验收→项目记忆；未解问题→05_CACHE；下一步→一行指令。
Why：实证长对话遵守率下降；AOS 实测 goal 14 轮后规则衰减。冲刷 = 工作记忆物化为文件记忆。

## 调研渠道纪律（最高优先级）

1. **调研类指令优先走高质量搜索通道**（Exa 类神经搜索插件，质量高于通用爬虫式搜索）。核验方法：看 web_search 返回头部归属——劣质渠道标识出现 = 未走优质通道，换法
2. **每次调研先验渠道再开工**：首查确认归属；若优质通道未生效（插件未加载），改用 read_page 直读权威源 + 多源交叉，禁止拿单一爬虫结果下结论
3. **结论分级**：单一来源=待验证；两个独立来源=可引用；官方文档/论文>技术博客>论坛>聚合站；搜索摘要 ≠ 原文，关键结论必须 read_page 回原文核对
4. 中文内容可补通用搜索，但优质通道/原文核对仍是主通道

## 入库四问（写入门禁）

写入 04_MEMORY / 09_REFERENCE 前逐条自问，任何一问不过 → 不入库：

1. **相关吗**（relevance）——与现有条目/当前任务域直接相关？
2. **新吗**（novelty）——不是已有条目的换皮？先查 INDEX/_index 与近邻条目
3. **可信吗**（confidence）——来源等级够（官方/双独立源）？单一来源=低置信，hook 必须标"待验证"
4. **有用吗**（utility）——未来检索场景明确？想不出场景=不存

**负例清单（出现即拒收）**：与现有条目语义重复（No Echo/Duplication）；能从规则或现有记忆推导；纯过程性细节（归 episodic/会话档案）；相对日期；未消解的自相矛盾（Contamination）。

**冲突处理**：写时只标记不裁决——状态型覆盖旧值留变更注释，**读时新值优先**；批量对账留给巡检或会话末低成本批量模型整理。

## 流程

1. **抓取**：用 web_search 发现来源、read_page/web_fetch 读正文；本地文件直接 read
2. **甄别**：判断与 09_REFERENCE 现有知识是否重复（查 `_index.md`）——重复则只补充增量
3. **入库**：写入 `09_REFERENCE/{domain}/{topic}.md`，头部含：来源 URL、抓取日期、可信度备注
4. **索引**：`09_REFERENCE/_index.md` 加一行指针（主题 + 一句话 hook），索引超 200 行时启用父子索引模式
5. **归位**：临时抓取产物放 `05_CACHE/{project}/{date}/`，禁止留在根目录

## gotchas（持续追加）

- 中文站点常需 read_page 而非 web_fetch（反爬）；Google 反爬时直接换搜索词，不硬刚
- 大批量抓取（>20 页）改用 workflow 并行，路由低成本批量模型
- 入库文件不复制进项目——项目只写路径引用（铁律 4）
